Raspberry Pi et Linux pour le robot

Le cerveau du canard est un ordinateur miniature sans écran ni clavier. Ce cours vous apprend à le préparer, à lui parler depuis un PC et à le conduire sans rien casser.

Durée : 60 min Niveau : débutant Prérequis : aucun Rôles : référent électronique et code, membres du banc

À la fin de ce cours, vous saurez

  • Dire ce qu'est la carte qui pilote le canard et ce qu'elle fait.
  • Préparer une carte mémoire avec le bon système.
  • Vous connecter au robot depuis un PC Windows, sans écran.
  • Utiliser 15 commandes texte et modifier un fichier.
  • Vérifier que les servos et le capteur d'équilibre sont vus, et lire un journal.
  • Appairer la manette, sécuriser l'image prête et éteindre proprement.

1. Un ordinateur complet sur une petite carte

Un Raspberry Pi est un mini-ordinateur sous Linux : processeur, mémoire, Wi-Fi, ports, tout est sur une seule carte. Le canard utilise le plus petit modèle, le Raspberry Pi Zero 2 W :

  • 4 cœurs : le processeur peut mener quatre calculs en parallèle ;
  • 512 Mo de mémoire vive, le plan de travail où tournent les programmes (c'est peu) ;
  • Wi-Fi pour nous y connecter, Bluetooth pour la manette ;
  • alimentation 5 V par un connecteur micro-USB ;
  • des broches GPIO (entrées/sorties) qui lisent ou écrivent un niveau électrique de 0 ou 3,3 V.
Exemple sur notre canard

Le Pi lit les contacts de pied sur GPIO22 (gauche, broche 15) et GPIO27 (droit, broche 13), et le capteur d'équilibre sur GPIO2 et GPIO3 (broches 3 et 5). Il parle aux 14 servos par un câble USB relié à la carte Waveshare, écoute la manette en Bluetooth et calcule la marche 50 fois par seconde.

Erreur classique. Mettre du 5 V sur une broche GPIO : le Pi grille. Et jamais le pack 2S (7,4 V) directement sur le Pi : c'est le régulateur 5 V (UBEC) qui l'alimente.

2. Le système : Raspberry Pi OS Lite, version Bookworm

Un système d'exploitation est le logiciel de base qui fait tourner les autres, comme Windows sur votre PC. Image mentale : le chef d'atelier qui répartit les machines (processeur, mémoire, carte, USB) entre les programmes. Sur le Pi, c'est Raspberry Pi OS, un Linux.

Nous prenons la version Lite, sans bureau graphique : tout se fait en tapant des commandes, ce qui laisse la mémoire au programme de marche. Et la version 64 bits nommée Bookworm, parce qu'elle fournit Python 3.11. Python est le langage de programmation de tout le logiciel du canard.

Pourquoi pas la version la plus récente. Les images récentes passent à Python 3.13. La bibliothèque qui exécute le réseau de marche, onnxruntime 1.18.1, n'y existe pas (issue #38 du dépôt Runtime) : la marche ne s'installe pas.
Erreur classique. Prendre la première version proposée par l'outil d'installation. Il faut aller chercher la version Lite 64 bits dont la description mentionne Bookworm, parfois rangée parmi les « autres » versions ou sous l'étiquette Legacy (ancienne version).

3. Préparer la carte microSD

Le Pi n'a pas de disque : tout est sur une carte microSD. Flasher une carte, c'est y copier un système complet ; elle est effacée au passage. On utilise le logiciel gratuit Raspberry Pi Imager, sur le PC.

  1. Insérer la carte dans le lecteur du PC. Débrancher les autres clés USB.
  2. Choisir le modèle : Raspberry Pi Zero 2 W.
  3. Choisir le système : Raspberry Pi OS Lite 64 bits Bookworm. Pour l'image prête du canard, prendre « Use custom » (utiliser une image personnalisée) et désigner directement le fichier ZIP téléchargé, sans le décompresser.
  4. Choisir le stockage : la carte microSD. Vérifier deux fois son nom et sa taille.
  5. Personnaliser : nom d'hôte (le nom du Pi sur le réseau, par exemple canard) ; nom d'utilisateur et mot de passe ; Wi-Fi (nom du réseau, mot de passe, pays FR) ; fuseau horaire et clavier français ; dans les services, activer SSH avec mot de passe (la connexion à distance, section 4).
  6. Écrire, laisser la vérification aller au bout, éjecter la carte.
Exemple sur notre canard

Pour l'image prête v0.2.3, on prend une carte de 32 Go. On peut y renseigner le Wi-Fi du FabLab, mais on garde l'utilisateur prévu, bdxv2 : avec un autre nom, les scripts lancés à la main demandent un réglage supplémentaire.

Erreur classique. Sélectionner le mauvais stockage, par exemple la clé de sauvegarde branchée à côté. Imager l'efface sans discuter.

4. Premier démarrage et connexion SSH

Glisser la carte dans le Pi, brancher l'alimentation sur le micro-USB marqué PWR IN. Le premier démarrage est plus long : le système s'installe et applique les réglages. La LED verte clignote quand il lit la carte.

Trouver l'adresse du Pi

Sur un réseau, chaque appareil a une adresse IP : quatre nombres séparés par des points. Trois façons de la trouver : taper ping canard.local dans PowerShell (le nom d'hôte suivi de .local marche souvent directement) ; regarder la liste des appareils sur la page de la box du FabLab ; ou, avec un écran et un clavier branchés, taper hostname -I.

Se connecter depuis Windows

SSH permet d'utiliser le terminal du Pi (la fenêtre où l'on tape des commandes) depuis le PC, par le réseau, de façon chiffrée. Ouvrir PowerShell (menu Démarrer, taper « PowerShell »), puis :

ssh utilisateur@adresse
ssh biscalab@canard.local     # une installation à nous
ssh bdxv2@bdxv2.local         # l'image prête du canard

À la première connexion, une question demande si l'on fait confiance à cette machine : taper yes. Puis le mot de passe : rien ne s'affiche pendant la frappe, c'est normal. L'invite biscalab@canard:~ $ se lit « utilisateur @ machine : dossier courant ».

Erreur classique. Après avoir reflashé une carte, SSH refuse avec « REMOTE HOST IDENTIFICATION HAS CHANGED » : le PC se souvient de l'ancien système. Taper ssh-keygen -R canard.local, puis se reconnecter.

5. Le terminal : chemins et 15 commandes

Le terminal (ou ligne de commande) remplace les clics par des ordres écrits. Sur la version Lite, c'est la seule interface. On écrit une commande, on valide par Entrée, le Pi répond.

Lire un chemin

Un chemin désigne un fichier comme une adresse postale, du plus général au plus précis. /home/biscalab/essais/note.txt : en partant de la racine /, dossier home, puis biscalab, puis essais, fichier note.txt. Raccourcis : ~ = votre dossier personnel ; . = le dossier où vous êtes ; .. = le dossier parent. Majuscules et minuscules comptent.

Trois touches font gagner du temps : Tab complète un nom commencé, ↑ rappelle la commande précédente, Ctrl+C interrompt un programme.

Erreur classique. Mettre sudo devant tout par réflexe. Les fichiers créés ainsi appartiennent à l'administrateur, et les scripts du robot ne peuvent plus les modifier ensuite. sudo seulement quand le système le demande.

6. Modifier un fichier avec nano

nano nom-du-fichier ouvre un éditeur de texte dans le terminal ; le fichier est créé s'il n'existe pas. On se déplace avec les flèches et on tape normalement. En bas, l'aide affiche les raccourcis : ^O signifie Ctrl+O.

  • Ctrl+O puis Entrée : enregistrer (O pour Write Out, écrire).
  • Ctrl+X : quitter. Si le fichier a changé, nano demande s'il faut enregistrer : Y (oui) ou N (non).
  • Ctrl+W : chercher un mot. Ctrl+K : couper la ligne.

Pour un fichier système, ajouter sudo : sudo nano /boot/firmware/config.txt.

Erreur classique. Copier une commande depuis un traitement de texte ou un téléphone : les guillemets droits " deviennent des guillemets typographiques, et la commande ou le fichier de réglages ne fonctionne plus.

7. Voir les périphériques et lire les journaux

Activer l'I²C pour le capteur d'équilibre

L'I²C est un bus à deux fils (SDA pour les données, SCL pour l'horloge) qui relie le Pi à des capteurs. Notre centrale inertielle, la BNO055, est dessus. Il est désactivé par défaut :

sudo raspi-config
  → Interface Options → I2C → Yes → Finish
sudo reboot
ls /dev/i2c*

La dernière commande doit afficher /dev/i2c-1. La BNO055 gère mal le dialogue avec le Pi sur ce bus. Remède documenté : ralentir le bus en ajoutant dtparam=i2c_arm_baudrate=10000 dans /boot/firmware/config.txt, ou passer la BNO055 en liaison série. Le projet d'origine n'a pas tranché ; nous déciderons sur le banc.

Voir la carte des servos

Linux montre chaque périphérique comme un fichier dans /dev. La carte Waveshare branchée en USB doit apparaître sous le nom /dev/ttyACM0 :

ls /dev/ttyACM*

Lire un journal

Un log (journal) est la suite de lignes qu'un programme écrit pendant qu'il tourne. Deux outils :

  • sudo dmesg | tail : les derniers messages du noyau, le cœur du système. Juste après avoir branché un câble USB, on y lit ce qui a été détecté.
  • journalctl -b : le journal de tous les services depuis le démarrage ; journalctl -p err -b ne garde que les erreurs. q pour quitter.

Un journal se lit par la fin : on cherche les dernières lignes contenant « error » ou « fail ».

Exemple sur notre canard

Sur le banc, ls /dev/ttyACM* ne renvoie rien. On débranche et rebranche le câble USB de la Waveshare, puis sudo dmesg | tail : si aucune ligne nouvelle n'apparaît, le Pi ne voit rien, il faut regarder le câble et l'adaptateur avant de soupçonner les servos.

8. Services et manette

Les services systemd

systemd est le gestionnaire de services de Linux. Image mentale : le gardien qui allume les machines le matin et les relance si elles s'arrêtent. Un service est un programme qu'il lance au démarrage.

systemctl list-units --type=service    # lister les services
systemctl status nom-du-service        # état et dernières lignes du journal
sudo systemctl stop nom-du-service     # arrêter maintenant
sudo systemctl disable nom-du-service  # ne plus lancer au démarrage
journalctl -u nom-du-service -f        # suivre son journal en direct

Sur l'image prête, la marche est lancée par le service open-duck-walk.service.

Erreur classique. Lancer un script de test pendant que le service de marche tourne. Deux programmes qui parlent en même temps aux servos par /dev/ttyACM0 se gênent. On arrête le service d'abord : sudo systemctl stop open-duck-walk.service.

Appairer la manette Xbox

La manette Bluetooth pilote le canard : les sticks donnent la direction, le bouton A met en pause. On l'appaire une fois avec bluetoothctl, qui ouvre sa propre invite :

sudo bluetoothctl
power on
agent on
default-agent
scan on                    # chercher les appareils
pair XX:XX:XX:XX:XX:XX     # adresse affichée pour la manette
trust XX:XX:XX:XX:XX:XX    # reconnexion automatique
connect XX:XX:XX:XX:XX:XX
scan off
quit

Pendant scan on, maintenir le petit bouton d'appairage de la manette jusqu'à ce que le logo clignote vite ; son adresse s'affiche avec son nom.

Exemple sur notre canard

Sans trust, il faudrait réappairer la manette à chaque démarrage. Le bouton Y (contrôle de la tête) est réputé dangereux pour la tête du canard : on ne l'utilise pas en démonstration.

9. L'image prête v0.2.3 et l'arrêt propre

Ce qu'elle apporte

Une image toute prête, basée sur Bookworm, s'écrit sur une carte de 32 Go et évite l'installation manuelle. Au démarrage, le pied appuyé choisit le mode : pied gauche = Head-Puppet (marionnette de tête), pied droit = Walk (marche), aucun pied = rien ne démarre. Le guide de l'image précise « en regardant le robot de face » : nous vérifierons sur notre canard quel pied lance quoi. La manette doit être allumée et appairée avant le démarrage.

Si le Pi ne trouve aucun réseau Wi-Fi connu, il crée son propre point d'accès nommé « Openduck », auquel on connecte le PC. Restent à faire, propres à chaque robot : le fichier ~/duck_config.json, les décalages de zéro des servos et la calibration du capteur d'équilibre. Sans eux, le canard ne démarre pas. Si la carte paraît presque pleine, agrandir le système : sudo raspi-config nonint do_expand_rootfs, puis sudo reboot.

Changer les identifiants tout de suite

Les identifiants par défaut, bdxv2 / ilovemyduck, sont publiés : n'importe qui à portée de Wi-Fi pourrait entrer. Dès la première connexion, passwd : taper l'ancien mot de passe, puis deux fois le nouveau (rien ne s'affiche). Même chose pour le point d'accès :

passwd
sudo nmcli connection modify Openduck wifi-sec.psk "nouveau-mot-de-passe"
sudo nmcli connection down Openduck
sudo nmcli connection up Openduck

L'image connaît aussi un réseau de secours préréglé, « Duckspot », dont les identifiants sont publics : à traiter de la même façon. Les nouveaux mots de passe se gardent chez le référent électronique et code, jamais dans le dépôt GitHub : le dépôt du club est public. Ce qu'on a fait est noté dans biscalab/INSTALL-biscalab.md.

Éteindre proprement

sudo poweroff

Attendre que la LED verte ait fini de clignoter et reste éteinte, puis seulement couper l'alimentation. Sur le robot : d'abord sudo poweroff, ensuite l'interrupteur de la batterie.

Pourquoi c'est comme ça. Le système écrit en permanence sur la carte (journaux, réglages). Couper au milieu d'une écriture peut abîmer la carte : le Pi ne démarre plus, il faut reflasher, et tout réglage non sauvegardé ailleurs est perdu. C'est pour cela qu'on commite duck_config.json après chaque calibration.
Erreur classique. Débrancher le pack pour « redémarrer » le robot quand il ne répond plus. On se reconnecte en SSH et on tape sudo reboot.

Exercice pratique au FabLab

Matériel : un Pi Zero 2 W, une carte microSD et un lecteur, une alimentation 5 V micro-USB, le PC Windows du FabLab avec Raspberry Pi Imager, le Wi-Fi du FabLab. Durée : environ 30 min, dont l'écriture de la carte.

  1. Flasher Raspberry Pi OS Lite 64 bits Bookworm, avec nom d'hôte canard-essai, votre utilisateur, un mot de passe, le Wi-Fi et SSH activé.
  2. Démarrer le Pi et patienter jusqu'à ce que ping canard-essai.local réponde dans PowerShell.
  3. Se connecter : ssh utilisateur@canard-essai.local, répondre yes, taper le mot de passe.
  4. Créer un dossier : pwd, mkdir essais, cd essais.
  5. Écrire un fichier : nano bonjour.txt, taper votre prénom et la date, Ctrl+O, Entrée, Ctrl+X.
  6. Le relire : cat bonjour.txt, puis ls -l pour voir sa taille et sa date.
  7. Éteindre : sudo poweroff, attendre que la LED reste éteinte, débrancher.

Résultat attendu : votre texte s'affiche à l'écran avec cat, et le Pi s'est éteint proprement. Notez dans le journal de séance ce qui vous a bloqué.

Auto-contrôle

Pourquoi Bookworm et pas la version la plus récente de Raspberry Pi OS ?

Bookworm fournit Python 3.11. Les versions récentes passent à Python 3.13, où onnxruntime 1.18.1 n'existe pas : la marche ne s'installe pas (issue #38).

Rien ne s'affiche quand je tape mon mot de passe SSH. Panne ?

Non, c'est voulu : le terminal n'affiche rien pendant la saisie d'un mot de passe. Tapez-le et validez.

Que désignent ~ et .. dans un chemin ?

~ est votre dossier personnel, .. le dossier parent de celui où vous êtes.

ls /dev/ttyACM* ne renvoie rien sur le banc. Que vérifier ?

Que la carte Waveshare est bien branchée en USB (câble, adaptateur), puis regarder sudo dmesg | tail juste après l'avoir rebranchée pour voir si le Pi la détecte.

Pourquoi ne jamais couper l'alimentation à chaud ?

Le système écrit sans cesse sur la carte microSD ; une coupure en pleine écriture peut la rendre illisible. Toujours sudo poweroff, puis attendre la LED.

À retenir

  • Le Pi Zero 2 W : 4 cœurs, 512 Mo, Wi-Fi, Bluetooth, 5 V en micro-USB, GPIO en 3,3 V seulement.
  • Raspberry Pi OS Lite 64 bits Bookworm, pour Python 3.11.
  • Imager : modèle, système, carte (vérifier deux fois), puis nom d'hôte, utilisateur, Wi-Fi, SSH.
  • ssh utilisateur@adresse depuis PowerShell ; le mot de passe ne s'affiche pas.
  • Un chemin se lit depuis / ; ~ = chez soi ; Tab complète.
  • Servos : /dev/ttyACM0. Capteur : I²C activé. Problème : dmesg et journalctl, lus par la fin.
  • Image prête : changer bdxv2 / ilovemyduck avec passwd dès la première connexion.
  • sudo poweroff, attendre la LED, puis couper. Jamais l'inverse.
