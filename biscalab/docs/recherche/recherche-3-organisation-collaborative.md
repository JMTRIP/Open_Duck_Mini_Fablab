# Organiser BiscaLab pour construire l'Open Duck Mini V2 — Recherche 3 : méthode, outils, kit de démarrage

*Recherche web du 1er octobre 2026. Chiffres GitHub, FreeCAD et Onshape vérifiés sur les pages officielles à cette date.*

## Synthèse
1. **Un seul dépôt GitHub** : fork public d'`apirrone/Open_Duck_Mini` dans une organisation gratuite « biscalab ». Tout ce qui est à nous va dans `biscalab/`. On ne modifie jamais les fichiers amont → « Sync fork » suffit.
2. **La CAO reste là où elle est pratique** : retouches de pièces amont dans une copie Onshape (le modèle amont est un document Onshape public) ; pièces nouvelles dans FreeCAD. Un fichier CAO = un éditeur à la fois.
3. **Git LFS inutile au départ** : STL petits, LFS demande la ligne de commande.
4. **Phases et jalons = plan d'achats** (6 phases) + phase 0. Pas de phase suivante sans fiche de test.
5. **Deux canaux** : Signal/WhatsApp pour échanger, GitHub pour décider et tracer. Photos sur le Nextcloud BiscaLab.

## 1. GitHub pour non-développeurs
- Plan Free pour organisations : dépôts illimités, Issues, Projects, 2 000 min Actions/mois, 500 Mo Packages ([pricing](https://github.com/pricing)). Création : Paramètres → Organisations → Nouvelle organisation ([doc FR](https://docs.github.com/fr/organizations/collaborating-with-groups-in-organizations/creating-a-new-organization-from-scratch)).
- **Au moins 2 propriétaires** (« ne pas attribuer à moins de deux personnes », [rôles](https://docs.github.com/fr/organizations/managing-peoples-access-to-your-organization-with-roles/roles-in-an-organization)) ; les autres membres.
- GitHub Team : 4 $/utilisateur/mois ; gratuit pour nonprofit enregistrée ([GitHub for Nonprofits](https://docs.github.com/en/nonprofit/nonprofit-teams-plan/getting-started-with-the-github-team-plan-for-nonprofits)) — éligibilité loi 1901 à vérifier, non nécessaire.
- **2FA** obligatoire pour propriétaires/créateurs de releases ; TOTP recommandé, SMS déconseillé ([doc](https://docs.github.com/fr/authentication/securing-your-account-with-two-factor-authentication-2fa/about-mandatory-two-factor-authentication)). Codes de récupération imprimés.
- **Fork vs clone** : fork = copie sur GitHub reliée à l'amont ; fork d'un dépôt public forcément public ([forks](https://docs.github.com/fr/pull-requests/collaborating-with-pull-requests/working-with-forks/about-forks)). **Issues désactivées par défaut dans un fork** → Settings → Features → Issues ([communauté](https://github.community/t/create-issues-for-forks/118975)). Sync : « Synchroniser la duplication → Mettre à jour la branche » ([doc FR](https://docs.github.com/fr/pull-requests/collaborating-with-pull-requests/working-with-forks/syncing-a-fork)). GitHub Desktop au premier clone : « Pour mon propre usage » ([doc FR](https://docs.github.com/fr/desktop/adding-and-cloning-repositories/cloning-and-forking-repositories-from-github-desktop)). Forker aussi `Open_Duck_Mini_Runtime`.
- Fonctions par priorité : Issues (modèles sans code, issue forms YAML, [doc FR](https://docs.github.com/fr/communities/using-templates-to-encourage-useful-issues-and-pull-requests/configuring-issue-templates-for-your-repository)) ; Projects (tableau/kanban/roadmap, 50 champs, [doc FR](https://docs.github.com/fr/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects)) ; Milestones ; Releases (2 Gio/fichier, 1 000 fichiers, [doc FR](https://docs.github.com/fr/repositories/releasing-projects-on-github/about-releases)) ; Markdown dans `docs/` plutôt que Wiki/Pages ([wikis](https://docs.github.com/fr/communities/documenting-your-project-with-wikis/about-wikis), [Pages](https://docs.github.com/fr/pages/getting-started-with-github-pages/what-is-github-pages)) ; Discussions superflues.
- Bonus : STL en 3D (< 10 Mo) et CSV en tableau (< 512 Ko) ([doc FR](https://docs.github.com/fr/repositories/working-with-files/using-files/working-with-non-code-files)).
- Limites : avertissement > 50 Mio, blocage > 100 Mio, 25 Mio par envoi navigateur, dépôt < 5 Go recommandé ([doc FR](https://docs.github.com/fr/repositories/working-with-files/managing-large-files/about-large-files-on-github)).
- Git LFS 2026 : 10 GiB stockage + 10 GiB/mois Free ; 250 GiB Team ([doc](https://docs.github.com/en/billing/concepts/product-billing/git-lfs)) ; pack 5 $/mois. Desktop installe LFS mais `git lfs track` = ligne de commande ([doc FR](https://docs.github.com/fr/desktop/configuring-and-customizing-github-desktop/about-git-large-file-storage-and-github-desktop)) ; `.gitattributes` à commiter ([doc FR](https://docs.github.com/fr/repositories/working-with-files/managing-large-files/configuring-git-large-file-storage)). Recommandation : pas de LFS tant qu'aucun fichier > 50 Mo ; `.gitattributes` binaire pour stl/3mf/FCStd/step.
- GitHub Desktop sans sélecteur de langue ([discussion](https://github.com/orgs/community/discussions/187662)) ; docs officielles en français.

## 2. Fichiers CAO en équipe
- FreeCAD 1.0 (18/11/2024) : nommage topologique corrigé, atelier Assembly natif ([LinuxFr](https://linuxfr.org/news/freecad-1-0)). 1.1 (25/03/2026) : aperçus PartDesign, poignées congés/chanfreins, Clarify Selection, Assembly/FEM ([OSArch](https://osarch.org/2026/03/25/freecad-1-1-released/)).
- `.FCStd` = zip (`Document.xml`, `GuiDocument.xml`, `.brp`) ([format](https://gitea.suzanne.soy/suzanne.soy/FreeCAD-Doc/raw/branch/master/localwiki/File_Format_FCStd.html)) ; git stocke une copie complète par version ([Arch Git](https://gitea.suzanne.soy/suzanne.soy/FreeCAD-Doc/raw/branch/master/localwiki/Arch_Git.html)). Pas de mode « dossier ». Palliatifs : compression 0 (Préférences → Général → Document ; nom d'auteur, licence) ([source](https://raw.githubusercontent.com/FreeCAD/FreeCAD/main/src/Gui/PreferencePages/DlgSettingsDocument.ui)) ; filtre zippey ([lambda.cx](https://blog.lambda.cx/posts/freecad-and-git/)), pas pour novices. Règle : un éditeur par fichier (issue assignée = verrou). Ignorer `*.FCBak`.
- Onshape : document amont public ; offre gratuite non commerciale, documents publics ([pricing](https://www.onshape.com/en/pricing)) ; « Make a copy » puis Export STL/STEP ([FarmBot](https://express.farm.bot/v1.1/extras/cad), [forum](https://forum.onshape.com/discussion/25413/what-is-the-easiest-way-to-be-able-to-copy-and-edit-an-assembly-that-belongs-to-someone-else)) ; versions, branches, merge ([aide](https://cad.onshape.com/help/Content/Primer/branching.htm)).

| | Onshape | FreeCAD |
|---|---|---|
| Retoucher une pièce amont | Historique paramétrique conservé | STEP = solide sans historique |
| Simultané | Temps réel, branches | Un éditeur par fichier |
| Hors ligne, données chez soi | Non, tout public | Oui |
| Apprentissage | Navigateur, rapide | Plus raide |

- Recommandation : retouches amont dans une copie Onshape « BiscaLab » ; pièces nouvelles dans FreeCAD, STEP à côté du `.FCStd`.
- Nommage : noms stables (`tibia-gauche.FCStd`), pas de `_v3_final` (références 3MF) ; `rev` dans `pieces.csv` et `CHANGELOG.md`.

## 3. Impression 3D en équipe
- Amont : PLA 15 % ; `foot_bottom_tpu.stl` TPU 40 % ([print_guide](https://github.com/apirrone/Open_Duck_Mini/blob/v2/docs/print_guide.md)). V1 = suivre l'amont.
- PETG pour pièces mécaniques (plus délicat) ; PLA-CF/PETG-CF = buse durcie ([Prusa matériaux](https://help.prusa3d.com/fr/materials)) ; TPU lent.
- Profils : Fichier → Exporter → lot de configuration (`.ini`) ; jamais « with Physical Printers » (clés API, IP) ([aide](https://www.help.prusa3d.com/article/how-to-import-and-export-custom-profiles-in-prusaslicer_382766)). 3MF par plateau : objets, positions, modificateurs, réglages, supports peints ([aide](https://help.prusa3d.com/article/saving-projects-as-3mf_1773)).
- Inserts M3 ([CNC Kitchen](https://cnckitchen.com/blog/tips-and-tricks-for-heat-set-inserts)) : trou droit ~1 mm plus profond ; fer +10-20 °C vs température d'impression (≈ 225 PLA, ≈ 245 PETG) ; 90 % au fer, finir à plat. Inserts de la BOM amont (trous dimensionnés) ; pièce test.
- Suivi : `pieces.csv` (piece, fichier, rev, qte, matiere, remplissage, couche, supports, 3mf, imprimee_par, date, statut, remarque).

## 4. Laser xTool P2S
- CO₂ 55 W, 600 × 305 mm, SVG/DXF/PNG/JPG/BMP, XCS et LightBurn ([The Gadgeteer](https://the-gadgeteer.com/2025/01/05/xtool-p2s-55w-desktop-co2-laser-cutter-review-a-laser-cutting-and-engraving-dream-machine/)) ; ~18 mm bois dur, 20 mm acrylique, spot ~0,15 × 0,2 mm, 233 CFM ([ArchitectureLab](https://www.architecturelab.net/xtool-p2s-55w-desktop-co2-laser-cutter-and-engraver-review/)).
- XCS gratuit, caméras ; LightBurn USB, pas de caméras, axe Z désactivé ([xTool](https://support.xtool.com/article/287)), 99/199 $ ([ThePricer](https://www.thepricer.org/how-much-does-lightburn-software-cost/)). **XCS suffit.**
- Kerf 0,15-0,25 mm CP 3 mm, 0,10-0,20 mm acrylique 3 mm ; mesure (trou − carré)/2 ([1laser](https://wiki.1laser.com/en/knowledge-base/popularization/kerf-compensation)) ; XCS kerf offset −1..+1 mm ([xTool](https://support.xtool.com/article/2426)).
- Matériaux : CP peuplier, PMMA coulé ; interdits PVC/vinyle, ABS, PC, PSE, carbone enduit ([Tulane](https://makerspace.tulane.edu/index.php/Laser_Cutter_Materials)).
- Usages : socle banc servo, gabarits de zéro, potence/harnais, caisse de transport, signalétique. Pas de redessin de la structure.

## 5. Méthode de projet
- Phases : les 6 du plan d'achats + phase 0 « Organisation » ; phase 2 = GO/NO-GO ; un milestone par phase, champ « Phase » dans Projects.
- Rituels : point hebdo 20 min (fait / à faire / bloqué) ; démo mensuelle ; journal `journal/AAAA-MM-JJ.md` (présents, fait, mesures, problèmes, décisions, photos).
- Fiche de test : objectif, montage, procédure, critère chiffré, résultat, photo/vidéo, décision.
- Definition of Done ([Scrum Guide](https://scrumguides.org/scrum-guide.html)) : pièce faite = imprimée, contrôlée, inserts, CSV à jour, photo ; tâche faite = issue fermée avec preuve.
- Achats : un acheteur (trésorier) ; issue « Achat » par commande ; validation bureau ; factures Nextcloud ; note de frais ; fournisseurs UE.
- Sécurité : pack 2S 18650 — charge sur surface incombustible, sac ignifuge, surveillance, arrêt si chauffe/gonflement ([guide LiPo](https://www.unmannedtechshop.co.uk/fr/blogs/knowledge-base/how-to-charge-lipo-batteries-safely-complete-guide)) ; stockage ~50 % ; consigne incendie EPFL ([EPFL](https://www.epfl.ch/campus/security-safety/batteries-au-lithium/)). Laser : présence, extraction, liste affichée. Banc : alim labo limitée.
- Documentation continue ([OSHWA](https://oshwa.org/resources/sharing-best-practices/)) : sources + formats lisibles, BOM, photos d'assemblage, versions sur le matériel.
- Licence : Apache-2.0 ([LICENSE](https://raw.githubusercontent.com/apirrone/Open_Duck_Mini/v2/LICENSE)) — copie de licence, mentions conservées, fichiers modifiés signalés, NOTICE repris ; pas de garantie, pas de marques ([choosealicense](https://choosealicense.com/licenses/apache-2.0/)). `CREDITS.md` + colonne `rev`.

## 6. Communication (5 à 8 personnes)
Signal ou WhatsApp « Canard » ; une décision/question technique = issue ; Discord amont (https://discord.gg/UtJZsgfQGe) suivi par 1-2 référents ; photos/vidéos sur Nextcloud `Canard/AAAA-MM-JJ/`, photos allégées (< 1 Mo) dans `docs/` ; pas de wiki séparé.

## 7. Formation express
5 gestes GitHub Desktop ([prise en main FR](https://docs.github.com/fr/desktop/overview/getting-started-with-github-desktop)) : cloner ; Fetch + Pull avant séance ; commiter (résumé verbe + objet) ; Push en fin de séance ; brancher + pull request. Sync fork mensuel par le référent.
Tutoriels : [OpenClassrooms](https://openclassrooms.com/fr/courses/7162856-gerez-du-code-avec-git-et-github) (6 h) ; [Grafikart](https://grafikart.fr/formations/git) (3 h 38, chapitre Desktop) ; [wiki FreeCAD FR](https://wiki.freecad.org/Main_Page/fr) et [FreeCAD-France](https://freecad-france.com) ; [aide PrusaSlicer FR](https://help.prusa3d.com/fr/category/prusaslicer_204) ; guide [Tnkr](https://tnkr.ai/explore/docs/open-duck-mini/open-duck-mini-v2#home) et `docs/assembly_guide.md` (« incomplete »).

## Kit de démarrage
Dépôt `biscalab/Open_Duck_Mini`, fork public, Issues activées, seul `biscalab/` est à nous :
```
Open_Duck_Mini/               ← amont : NE PAS MODIFIER
├── print/  docs/  mini_bdx/ …
└── biscalab/
    ├── README.md  CREDITS.md  CHANGELOG.md
    ├── docs/ (conventions.md, securite.md, guide-github-desktop.md, photos/)
    ├── journal/   tests/   achats/achats.csv
    ├── cad/ (onshape-liens.md, freecad/, step/)
    ├── print/ (stl/, 3mf/, profiles/biscalab-bundle.ini, pieces.csv)
    ├── laser/ (svg-dxf/, xcs/)
    └── electronics/
```
`.gitattributes` (`*.stl *.3mf *.FCStd *.step binary`), `.gitignore` (`*.FCBak`, `*.gcode`, `Thumbs.db`). `Open_Duck_Mini_Runtime` forké à part.
Conventions : minuscules sans accents/espaces, tirets ; commits verbe + objet ; branches `prenom/sujet` ; labels `phase-0..6`, `impression`, `laser`, `cao`, `elec`, `code`, `achat`, `securite`, `bloque`, `aide-bienvenue` ; modèles d'issues Tâche, Problème, Achat, Test.
5 règles d'or : (1) pas sur GitHub = n'existe pas ; (2) pull en arrivant, push en partant, un éditeur par fichier CAO ; (3) jamais de fichier amont modifié ; (4) pas de phase/achat suivant sans fiche de test ; (5) sécurité non négociable.
Checklist première réunion (~1 h 30) : objectif/phases/budget ; rôles ; comptes GitHub + TOTP ; fork, Issues, labels, milestones, Project ; GitHub Desktop + 5 gestes ; copie Onshape + réglages FreeCAD ; lot PrusaSlicer + pièce test inserts ; Signal, Nextcloud, Discord ; `securite.md` ; issues phase 1 + date du prochain point.
